# ไอเดีย: พยากรณ์สุขภาพสัตว์เลี้ยงจากพฤติกรรมประจำวัน

สำหรับ Sea x OpenAI Regional Codex Hackathon Thailand
วันงาน 21 พ.ย. 2026 | ปิดรับสมัคร 23 ต.ค. 2026 | ทีม 3–4 คน | โค้ดหลักต้องเขียนในวันงาน
แนวทาง: **ข้อ 1 (Autonomous & Adaptive AI) + ข้อ 3 (Deep Domain AI)**

## 1. สรุปสั้น

เจ้าของมักรู้ว่าสัตว์ป่วยก็ต่อเมื่ออาการชัดแล้ว ระบบนี้ให้เจ้าของบันทึกเบามาก ๆ สองแบบ
- **บันทึกประจำวัน:** ถ่ายรูปชามอาหารและน้ำ 1 รูป หรือกด "วันนี้ปกติดี"
- **บันทึกตามเหตุการณ์:** อาการอื่น เช่น อาเจียนหรืออุจจาระผิดปกติ กรอกเมื่อเกิดเหตุ ถ่ายรูปส่งให้ระบบบันทึกพร้อมเวลา

แล้ว agent เรียนรู้ "ค่าปกติของตัวนั้นโดยเฉพาะ" (ค่าเฉลี่ยเคลื่อนที่ 7–14 วัน) ไม่ใช่ค่าเฉลี่ยทั่วไป
เมื่อพฤติกรรมเบี่ยงจากค่าปกติของตัวเอง เช่น กินน้อยลง 3 วันติด ก็เตือนพร้อมเหตุผลที่อ่านเข้าใจ
โดยดูหลายสัญญาณรวมกัน และแนะนำขั้นต่อไป (สังเกตเพิ่ม / นัดสัตวแพทย์ / พบทันที)
พร้อมกราฟก่อน-หลังและสรุปหนึ่งหน้าสำหรับส่งสัตวแพทย์
มี**ปุ่มฉุกเฉิน** สำหรับอาการอันตราย เช่น ปัสสาวะไม่ออก หรืออุจจาระมีเลือด ระบบแนะนำให้พบสัตวแพทย์ทันที

**ไม่ใช่การวินิจฉัยและไม่ระบุชื่อโรค** ระบบบอกแค่ "พฤติกรรมเบี่ยงจากปกติของตัวนี้" และ
"รูปแบบที่พบเป็นสิ่งที่สัตวแพทย์มักตรวจเพิ่ม" สัตวแพทย์เป็นผู้ตัดสินเสมอ

## 2. ปัญหา

- อาการเริ่มต้นของสัตว์เลี้ยงเล็กน้อยและค่อยเป็นค่อยไป เจ้าของจึงมองข้าม
- สัตว์แต่ละตัวปกติไม่เท่ากัน (แมวตัวหนึ่งกินวันละ 3 มื้อ อีกตัวกิน 5) เกณฑ์ทั่วไปจับไม่ได้
- คนที่ไม่ได้อยู่กับสัตว์ตลอดวันเห็นแค่ช่วงเช้ากับเย็น และเลี้ยงหลายตัว จึงสังเกตการกินการดื่มของแต่ละตัวไม่ได้
- สัตว์หลายตัว โดยเฉพาะแมว ซ่อนอาการเก่ง สัญญาณแรก เช่น กินน้อยลงหรือดื่มน้ำมากขึ้น จึงหลุดไป
- ตอนไปหาหมอ เจ้าของมักจำรายละเอียดย้อนหลังไม่ได้ว่าเปลี่ยนไปเมื่อไหร่

หลักฐานภายนอก (สถิติเจ้าของสัตว์เลี้ยงไทย, งานวิจัยการตรวจจับความผิดปกติจากพฤติกรรม): **ยังไม่ได้ค้น** ต้องหาก่อนอ้างในใบสมัคร

## 3. สิ่งที่สร้าง

```
บันทึกประจำวัน: รูปชามอาหาร+น้ำ 1 รูป หรือกด "วันนี้ปกติดี"
        |
        |        บันทึกตามเหตุการณ์: อาเจียน/อุจจาระผิดปกติ/อื่น ๆ + รูป + เวลา
        |                |
        +-------+--------+
                v
[ตัวสร้างค่าปกติรายตัว: โค้ดสถิติ]   baseline + ช่วงปกติของตัวนั้น (ค่าเฉลี่ยเคลื่อนที่ 7–14 วัน)
        |
        v
[ตัวตรวจแนวโน้ม: โค้ด]   ดูหลายสัญญาณรวมกัน: กินน้อยลง N วันติด + น้ำเพิ่มผิดปกติ + เหตุการณ์ซ้ำ ฯลฯ
        |
        +--> [กฎสัญญาณอันตราย: โค้ด]  เช่น ไม่กินเลยนานเกินเกณฑ์, ถ่ายเป็นเลือด -> แนะนำพบหมอทันที
        |            ^
        |            +-- [ปุ่มฉุกเฉิน: เจ้าของกดเอง] เช่น ปัสสาวะไม่ออก, อุจจาระมีเลือด (ข้ามตัวตรวจแนวโน้ม)
        |
        v
[LLM: อธิบายเหตุผล + เรียบเรียงสรุปให้หมอ] (ตัวเลข/วันที่ทุกจุดมาจากข้อมูล)
        |
        v
[Agent ตัดสินขั้นต่อไป: สังเกตเพิ่ม / นัดหมอ / พบทันที] -> ส่งต่อคน (เจ้าของ/สัตวแพทย์)
```

หลักการ:
- **โค้ดตัดสินสิ่งที่ผิดไม่ได้** (ค่า baseline, จำนวนวัน, สัญญาณอันตราย) LLM ทำแค่ภาษาและการอ่านรูป
- **ข้อ 3:** กฎสุขภาพสัตว์ต้องถอดจากความรู้สัตวแพทย์ (ชนิด/อายุ ต่างกัน เกณฑ์ต่างกัน)
- **ข้อ 1:** agent ปรับ baseline เมื่อข้อมูลเพิ่ม เลือกขั้นต่อไปเอง และส่งต่อคนเมื่อไม่แน่ใจ
- **รูปชามอาหาร/น้ำ:** ระบบอ่านระดับที่เหลือจากรูปเป็นข้อมูลประกอบ เจ้าของยืนยันหรือแก้ได้ในแตะเดียว
  ความแม่นยำของการอ่านรูปพิสูจน์ยาก จึงไม่ให้เป็นตัวตัดสินเดี่ยว ๆ (ข้อมูลจำลองใช้ค่าระดับตรง ๆ)
- **ปุ่มฉุกเฉิน:** ตอบแค่ "ควรพบสัตวแพทย์ทันที" พร้อมสรุปเวลาและอาการให้หมอ ไม่ประเมินความรุนแรงเอง
  รายการอาการต้องมาจากสัตวแพทย์ (ดูหัวข้อ 9)

## 4. Demo (ประมาณ 3 นาที)

1. สัตว์ตัวอย่าง 1 ตัว ข้อมูลจำลอง 30 วัน (สร้างเอง ไม่ใช่ข้อมูลจริง) มีป้ายบอกทุกหน้าจอ
2. หน้าบันทึกประจำวัน: ถ่ายรูปชาม 1 รูป หรือกด "วันนี้ปกติดี" จบในแตะเดียว
3. กราฟ "ก่อน-หลัง": เส้นปกติของตัวนั้น กับช่วงที่เริ่มเบี่ยง จุดที่ระบบเตือน
4. เทียบ: เกณฑ์ค่าเฉลี่ยทั่วไป (ไม่เตือน) vs baseline รายตัว (เตือนวันที่ 3)
5. บันทึกตามเหตุการณ์: เจ้าของถ่ายรูปอาเจียน/อุจจาระผิดปกติ ระบบบันทึกพร้อมเวลา แล้วเห็นว่าถูกรวมกับสัญญาณอื่นในการเตือน
6. กดดูเหตุผล และสรุปสำหรับสัตวแพทย์ (หน้าเดียว) ใช้คำว่ารูปแบบนี้สัตวแพทย์มักตรวจเพิ่ม ไม่ระบุชื่อโรค
7. กดปุ่มฉุกเฉิน (เช่น ปัสสาวะไม่ออก) และเคสสัญญาณอันตราย ให้เห็นว่าข้ามไปแนะนำพบหมอทันที
8. ใส่เคส "ผันผวนปกติ" ให้เห็นว่าระบบไม่เตือนเกินเหตุ

## 5. วัดผลยังไง

- **ตรวจจับได้เร็วแค่ไหน:** กี่วันหลังเริ่มเบี่ยง ระบบเตือน (ทดสอบกับเคสจำลองที่ฝังความผิดปกติไว้)
- **เตือนเกินเหตุ:** อัตราเตือนผิดในช่วงข้อมูลปกติ (false alarm)
- **baseline รายตัว vs ค่าเฉลี่ยทั่วไป:** เทียบสองวิธีบนชุดเคสเดียวกัน
- **หลายสัญญาณ vs สัญญาณเดียว:** เทียบว่ารวมกินน้อย/น้ำเพิ่ม/เหตุการณ์ แล้วเตือนเร็วขึ้นหรือเตือนเกินเหตุมากขึ้นแค่ไหน
- **สัญญาณอันตราย และปุ่มฉุกเฉิน:** ต้องจับได้ครบทุกเคสในชุดทดสอบ
- **ข้อเท็จจริงในสรุปให้หมอ:** ตัวเลขทุกจุดตรงกับข้อมูล
- ทุกตัวเลขมาจากข้อมูลจำลอง ต้องเขียนในใบสมัครตามนั้น

## 6. ใช้ Codex ตรงไหน (เกณฑ์ตัดสิน)

- เขียนตัว baseline รายตัวและตัวตรวจแนวโน้ม
- สร้างข้อมูลจำลองรายวันและชุดเคสที่ฝังความผิดปกติ/สัญญาณอันตราย
- เขียน eval harness (ความเร็วตรวจจับ, false alarm)
- เขียนหน้าบันทึกประจำวัน หน้าบันทึกเหตุการณ์ และปุ่มฉุกเฉิน
- เขียนหน้ากราฟและสรุปให้หมอ
- refactor เมื่อเปลี่ยนกฎหรือเกณฑ์

ต้องระบุตรงนี้ในใบสมัครให้ชัด

## 7. เทียบกับแนวทางและเกณฑ์ของผู้จัด

- **ข้อ 3:** ความรู้สัตวแพทย์ → กฎและเกณฑ์ต่อชนิด/อายุ
- **ข้อ 1:** agent เรียนรู้ baseline ตัดสินขั้นต่อไป ส่งต่อคนเมื่อไม่แน่ใจ มี guardrail
- **จุดขาย:** พยากรณ์แนวโน้มรายตัว กราฟก่อน-หลังชัดใน demo
- เกณฑ์: problem framing, build quality, depth of thinking, การใช้ Codex

## 8. ขอบเขต 1 วัน

ถ้าเวลาไม่พอให้ตัดจากท้าย

1. ข้อมูลจำลอง + baseline รายตัว (ค่าเฉลี่ยเคลื่อนที่ 7–14 วัน)
2. ตัวตรวจแนวโน้มหลายสัญญาณ + กฎสัญญาณอันตราย + ปุ่มฉุกเฉิน
3. หน้าบันทึกประจำวัน (ปุ่ม "วันนี้ปกติดี" + อัปโหลดรูป)
4. หน้ากราฟก่อน-หลัง + เหตุผลการเตือน
5. LLM เรียบเรียงสรุปให้หมอ
6. บันทึกตามเหตุการณ์ (ถ่ายรูป + เวลา)
7. eval (เร็วแค่ไหน / เตือนเกิน)
8. อ่านรูปชามอาหาร/ท่าทางด้วย vision (ส่วนเสริม ความแม่นยำพิสูจน์ยาก ทำเป็นข้อมูลประกอบ ไม่ใช่ตัวตัดสิน)

## 9. ความเสี่ยงและสิ่งที่ยังต้องตรวจ

**ความเสี่ยง**
- **ถูกมองเป็นการวินิจฉัย:** ต้องมีข้อความชัดทุกหน้าจอว่าไม่ใช่การวินิจฉัย และให้สัตวแพทย์ตัดสิน ห้ามระบุชื่อโรค
- **เตือนเกิน/ไม่เตือน:** เตือนเกินทำให้เจ้าของเมิน เตือนขาดอันตราย ต้องวัดทั้งสองด้าน
- **ข้อมูลจำลองทั้งหมด:** ต้องบอกตรง ๆ ว่ายังไม่ได้พิสูจน์กับสัตว์จริง
- **ข้อมูลเริ่มต้นน้อย:** baseline ต้องการข้อมูลหลายวัน ต้องออกแบบช่วง "กำลังเรียนรู้" (cold start)
- **ของใกล้เคียงมีอยู่:** แอปบันทึกสุขภาพสัตว์เลี้ยง/อุปกรณ์สวมใส่ (smart collar) มีในตลาด ยังไม่ได้ค้น ต้องหาจุดต่างให้ชัด
  (จุดต่างที่คิดไว้: เหตุผลที่อธิบายได้ + สรุปให้หมอ + ไม่ต้องใช้อุปกรณ์)

**ยังไม่ได้ตรวจ**
- [ ] เกณฑ์สัญญาณอันตรายที่ถูกต้องตามสัตวแพทย์ (ต้องหาแหล่งหรือผู้เชี่ยวชาญ ห้ามเดาเอง)
- [ ] รายการอาการของปุ่มฉุกเฉิน (เช่น ปัสสาวะไม่ออก อุจจาระมีเลือด) ว่าครบและถูกต้องตามสัตวแพทย์
- [ ] เกณฑ์ของบันทึกเหตุการณ์ (อาเจียน/อุจจาระผิดปกติ กี่ครั้งในกี่วันถึงควรนับเป็นสัญญาณ)
- [ ] ช่วง 7–14 วันของค่าเฉลี่ยเคลื่อนที่เหมาะกับสุนัข/แมวและแต่ละอายุหรือไม่
- [ ] เกณฑ์พฤติกรรมปกติต่อชนิด/อายุ (สุนัข/แมว)
- [ ] ผลิตภัณฑ์คู่แข่งและงานวิจัยการตรวจจับความผิดปกติจากพฤติกรรมสัตว์
- [ ] สถิติเจ้าของสัตว์เลี้ยงในไทยและพฤติกรรมพาไปหาหมอ
- [ ] ฟอร์มสมัครจริงและต้องให้สมาชิกทุกคนสมัครหรือไม่

## 10. Prototype (ออกแบบ)

เป็นแบบร่างสำหรับลงมือในวันงาน ยังไม่มีโค้ด (กติกา: โค้ดหลักต้องเขียนในวันงาน)
ตัวเลขและเกณฑ์ในหัวข้อนี้เป็น**ค่าตั้งต้นสำหรับ demo** ต้องจูนด้วย eval ไม่ใช่เกณฑ์ทางสัตวแพทย์ (ดูหัวข้อ 9)

### 10.1 รูปแบบ

เว็บแอปแบบ mobile-first (เจ้าของใช้มือถือ) เปิดบนเบราว์เซอร์ ไม่ต้องติดตั้ง
ทุกหน้ามีแถบคงที่: "ข้อมูลจำลองเพื่อสาธิต ไม่ใช่ข้อมูลสัตว์จริง | ไม่ใช่การวินิจฉัย สัตวแพทย์ตัดสินเสมอ"

Stack ที่เสนอ (ยังไม่ได้ตกลงกับทีม): TypeScript ทั้งระบบ, Next.js, กราฟด้วยไลบรารีกราฟมาตรฐาน,
LLM ผ่าน OpenAI API, ข้อมูลเก็บเป็นไฟล์ JSON/SQLite ให้เบาที่สุด ไม่ต้องมีระบบล็อกอิน

```
+--------------------------------------+
```

- ถ่ายรูป: ระบบอ่านระดับอาหารและน้ำที่เหลือ แสดงผลเป็นตัวเลือก (หมด / ครึ่ง / เหลือมาก) ให้เจ้าของแตะยืนยันหรือแก้
- "วันนี้ปกติดี": บันทึกค่าที่อยู่ในช่วงปกติของตัวนั้น ไม่ต้องกรอกอะไรเพิ่ม

**หน้า 2 บันทึกเหตุการณ์** เลือกประเภท (อาเจียน / อุจจาระผิดปกติ / อื่น ๆ) แนบรูป ระบบประทับเวลาให้
ช่องโน้ตเป็นข้อความอิสระ ไม่บังคับ แสดงรายการเหตุการณ์ย้อนหลังเรียงตามเวลา

**หน้า 3 ฉุกเฉิน** กดแล้วเลือกอาการจากรายการสั้น ๆ (เช่น ปัสสาวะไม่ออก อุจจาระมีเลือด)
ผลลัพธ์มีข้อความเดียว: "ควรพบสัตวแพทย์ทันที" พร้อมปุ่มโทรคลินิก (ใส่เบอร์เอง) และปุ่มสร้างสรุปให้หมอ
ไม่ประเมินความรุนแรง ไม่บอกชื่อโรค รายการอาการต้องผ่านสัตวแพทย์ก่อนใช้จริง

**หน้า 4 แนวโน้มและเหตุผลการเตือน**

```
+--------------------------------------+
| มะลิ: ปริมาณอาหารที่กิน (14 วัน)      |
|  1.0 |--o--o--o--o--o--o-             |
|      |  ช่วงปกติของมะลิ (แถบเทา)      |
|  0.5 |                  \o--o--o <-เตือน|
|      +--------------------------> วัน |
|                                      |
| ทำไมถึงเตือน                          |
| - กินน้อยกว่าช่วงปกติของมะลิ 3 วันติด |
|   (วันที่ 18-20 เฉลี่ย 0.55 จาก 0.9) |
| - ดื่มน้ำมากกว่าปกติ 3 วันติด         |
| - อาเจียน 2 ครั้งใน 3 วัน (รูป 2 รูป)  |
|                                      |
| ขั้นต่อไปที่แนะนำ: นัดสัตวแพทย์        |
| รูปแบบนี้เป็นสิ่งที่สัตวแพทย์มักตรวจเพิ่ม|
| [ สร้างสรุปให้หมอ ]                   |
|                                      |
| [ดูเทียบ: ค่าเฉลี่ยทั่วไป (ไม่เตือน)]  |
+--------------------------------------+
```

- กราฟมีเส้นค่าจริง แถบช่วงปกติรายตัว และจุดที่ระบบเตือน
- ปุ่มสลับเทียบ "เกณฑ์ค่าเฉลี่ยทั่วไป" กับ "baseline รายตัว" ใช้ในช่วง demo

**หน้า 5 สรุปสำหรับสัตวแพทย์ (หน้าเดียว พิมพ์หรือส่งได้)**
ข้อมูลสัตว์, ไทม์ไลน์ว่าเริ่มเปลี่ยนเมื่อไหร่, กราฟก่อน-หลัง, รายการเหตุการณ์พร้อมรูปและเวลา,
ข้อความคงที่ท้ายหน้า "ระบบนี้ไม่ใช่การวินิจฉัย ข้อมูลทั้งหมดมาจากการบันทึกของเจ้าของ (ในเดโมคือข้อมูลจำลอง)"

### 10.3 ข้อมูล

```
Pet        { id, name, species: dog|cat, ageYears }
DailyLog   { petId, date, foodLevel: 0..1, waterLevel: 0..1, source: normalButton|photo, photoUrl? }
Event      { petId, timestamp, type: vomit|abnormalStool|other, photoUrl?, note? }
Emergency  { petId, timestamp, symptom }
Alert      { petId, date, level: observe|bookVet|seeNow, signals[], evidence[] }
```

- `foodLevel`/`waterLevel` เป็นสัดส่วนเทียบกับปริมาณที่ให้ในวันนั้น
- `evidence` คือรายการวันที่และตัวเลขที่ใช้ตัดสิน LLM ต้องใช้แค่ข้อมูลนี้

### 10.4 ตรรกะตรวจจับ (โค้ดล้วน ไม่ใช้ LLM)

1. **Baseline:** ค่ากลางและความผันผวนปกติของแต่ละสัญญาณจากข้อมูล 14 วันล่าสุด (median/MAD) ต้องมีอย่างน้อย 7 วัน
   ก่อนหน้านั้นแสดงสถานะ "กำลังเรียนรู้ค่าปกติของมะลิ" และไม่เตือน (cold start)
2. **เบี่ยง:** วันหนึ่งนับว่าเบี่ยงเมื่อค่าห่างจาก median เกิน k × MAD (ค่าตั้งต้น k = 2.5 ปรับด้วย eval)
3. **แนวโน้ม:** เบี่ยงทางเดียวกันติดต่อกันอย่างน้อย N วัน (ค่าตั้งต้น N = 3)
4. **หลายสัญญาณ:** นับสัญญาณที่เบี่ยงพร้อมกัน (กิน, น้ำ) บวกเหตุการณ์ซ้ำในช่วงเวลาสั้น
5. **ระดับ:**
   - สัญญาณเดียวเบี่ยง N วัน -> `observe` (สังเกตเพิ่ม)
   - หลายสัญญาณ หรือมีเหตุการณ์ซ้ำ -> `bookVet` (นัดสัตวแพทย์)
   - กฎอันตราย หรือกดปุ่มฉุกเฉิน -> `seeNow` (พบทันที) ข้ามขั้น 1-5
6. **ไม่แน่ใจ:** ข้อมูลขาดหาย (ไม่ได้บันทึกหลายวัน) ให้ถามเจ้าของ ไม่เดา
7. **Baseline ปรับตามเวลา:** ไม่นับวันที่ถูกเตือนเข้าไปในการคำนวณ baseline เพื่อไม่ให้ค่า "ปกติ" ไหลตามอาการ

ค่า k, N และจำนวนเหตุการณ์ที่นับเป็นสัญญาณ เป็นค่าตั้งต้นที่ยังไม่ผ่านสัตวแพทย์

### 10.5 บทบาทของ LLM และ guardrail

- รับ: JSON ของ `Alert` (สัญญาณ, วัน, ตัวเลข) เท่านั้น
- ทำ: เขียนเหตุผลเป็นภาษาอ่านง่าย และเรียบเรียงสรุปให้หมอ
- ตรวจหลังตอบด้วยโค้ด: ตัวเลขและวันที่ทุกจุดต้องตรงกับ `evidence`, ห้ามมีชื่อโรคหรือคำวินิจฉัย (ตรวจจากรายการคำต้องห้าม),
  ต้องมีข้อความ "ไม่ใช่การวินิจฉัย" ถ้าไม่ผ่านให้ใช้ข้อความแม่แบบที่โค้ดสร้างแทน
- อ่านรูปชามอาหาร (ส่วนเสริม): ได้แค่ระดับที่เหลือ เจ้าของยืนยันก่อนบันทึกเสมอ

### 10.6 ชุดข้อมูลจำลอง (สร้างเองด้วย Codex ใช้ทั้ง demo และ eval)

| เคส | สัตว์ | ลักษณะ | ผลที่คาด |
|---|---|---|---|
| A เบี่ยงค่อยเป็นค่อยไป | แมว "มะลิ" | วัน 1-17 ปกติ วันที่ 18 เริ่มกินน้อยลงและดื่มน้ำเพิ่ม วันที่ 21-22 อาเจียน | เตือน `observe` วันที่ 20 แล้วขึ้น `bookVet` เมื่อมีอาเจียนซ้ำ |
| B สัญญาณอันตราย | สุนัข | ปกติ แล้วมีอุจจาระมีเลือด / กดฉุกเฉิน | `seeNow` ทันที |
| C ผันผวนปกติ | แมวตัวอื่น | กินสลับมากน้อยตามวัน แต่ไม่เบี่ยงต่อเนื่อง | ไม่เตือน |
| D ค่าปกติต่างกัน | แมวกิน 3 มื้อ vs 5 มื้อ | ระดับเท่ากันแต่ค่าปกติของตัวไม่เท่ากัน | ค่าเฉลี่ยทั่วไปตัดสินผิด baseline รายตัวถูก |

- ใส่ noise สุ่มพร้อม seed คงที่ เพื่อให้ eval ซ้ำได้
- ทุกเคสมีป้าย "ข้อมูลจำลอง" ในไฟล์และบนหน้าจอ

### 10.7 โครงโมดูล (ให้ Codex ทำทีละชิ้น)

```
data/simulate      สร้างเคส A-D
core/baseline      median/MAD, cold start
core/detect        แนวโน้ม หลายสัญญาณ ระดับการเตือน
core/danger        กฎอันตราย + ปุ่มฉุกเฉิน
core/guard         ตรวจผล LLM (ตัวเลข ชื่อโรค disclaimer)
llm/explain        เหตุผลการเตือน + สรุปให้หมอ
eval/run           ความเร็วตรวจจับ, false alarm, baseline vs ทั่วไป, ฉุกเฉินครบ
ui/*               หน้า 1-5
```

ลำดับลงมือตรงกับหัวข้อ 8 ถ้าเวลาไม่พอให้ตัดจากท้าย

### 10.8 สิ่งที่ตัดสินใจไม่ได้เองและต้องถามทีม/ผู้เชี่ยวชาญ

- Stack สุดท้าย ใครถนัดอะไร
- รายการอาการปุ่มฉุกเฉิน และกฎอันตราย
- ค่า k, N และเกณฑ์นับเหตุการณ์ตามชนิด/อายุ
- ใช้รูปจริงหรือรูปตัวอย่างในเดโม (ไม่ควรใช้รูปสัตว์ป่วยจริงโดยไม่ได้ขออนุญาต)
