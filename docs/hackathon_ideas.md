# ไอเดีย Sea x OpenAI Regional Codex Hackathon Thailand

- วันงาน: 21 พ.ย. 2026 (8:30–21:00) | ปิดรับสมัคร: 23 ต.ค. 2026
- ทีม 3–4 คน รับ 40 ทีม | การพัฒนาหลักต้องทำในวันงาน
- เกณฑ์ตัดสิน: Problem framing, Build quality, Depth of thinking, การใช้ Codex

---

## 1. แนวทางทั้ง 3 ข้อ อธิบายสั้น ๆ

### ข้อ 1: Autonomous & Adaptive AI
- **แก่น:** AI ที่ลงมือทำงานแทนคนได้เอง ปรับแผนเมื่อสถานการณ์เปลี่ยน และไว้ใจได้โดยไม่ต้องมีคนเฝ้า
- **วิธีสร้าง:** ตั้งเป้าหมายให้ agent → ให้เครื่องมือ (API, DB) → วนลูปวางแผน/ลงมือ/ตรวจผล → ใส่ guardrail และส่งต่อคนเมื่อไม่แน่ใจ → ทดสอบกรณีผิดปกติ
- **เวลาส่วนใหญ่ไปที่:** ความทนทานของ agent และการทดสอบ

### ข้อ 2: AI-Native Products & Operations
- **แก่น:** ผลิตภัณฑ์/วิธีทำงานที่ออกแบบใหม่โดยมี AI เป็นแกน ถ้าเอา AI ออกก็ใช้ไม่ได้
- **วิธีสร้าง:** เลือกกระบวนการที่ช้า/แพง → ออกแบบใหม่รอบ AI → ทำประสบการณ์ผู้ใช้ให้ AI ขับตั้งแต่ต้นจนจบ → วัดว่าดีกว่าวิธีเดิมแค่ไหน
- **เวลาส่วนใหญ่ไปที่:** การออกแบบผลิตภัณฑ์และประสบการณ์ผู้ใช้

### ข้อ 3: Deep Domain AI
- **แก่น:** AI ที่เก่งเรื่องเดียวในวงการเดียว ด้วยกฎ ข้อมูล และวิธีคิดของผู้เชี่ยวชาญ
- **วิธีสร้าง:** เลือกวงการและงานจริง → ถอดกฎ/เกณฑ์/ข้อยกเว้น → ผสมกฎกับ LLM (กฎทำส่วนที่ต้องแม่น, LLM ตีความและอธิบาย) → ใช้ข้อมูลจริง → ตรวจเทียบการตัดสินของผู้เชี่ยวชาญ
- **เวลาส่วนใหญ่ไปที่:** การเข้าใจโดเมนและใส่ความรู้ลงระบบ

| | ข้อ 1 | ข้อ 2 | ข้อ 3 |
|---|---|---|---|
| ถามว่า | agent ไว้ใจได้ไหม | ผลิตภัณฑ์ใหม่จริงไหม | เข้าใจโดเมนลึกไหม |
| ต้องมีจุดแข็งด้าน | วิศวกรรม agent | การออกแบบผลิตภัณฑ์ | ความรู้เฉพาะวงการ |
| ความเสี่ยงใน 1 วัน | พิสูจน์ความไว้ใจยาก | คิดผลิตภัณฑ์ใหม่ทั้งชิ้นหนัก | ต้องหาข้อมูลโดเมนให้ทัน |
| ตรงประสบการณ์เรา | ปานกลาง | ต่ำ | **สูง** |

> **Domain** = สาขา/วงการ/อุตสาหกรรมเฉพาะทางที่มีความรู้และกฎของตัวเอง (เช่น เกษตร การเงิน ประกันภัย)

## 2. ไอเดียแนวทางเดี่ยว

### ข้อ 1: SecOps Triage Agent (ต่อยอดฝึกงาน Runexy)
- **ใคร:** ทีม IT/ความปลอดภัยของบริษัทขนาดกลางที่มีช่องโหว่ (CVE) เข้ามาวันละหลายร้อยรายการ
- **ปัญหา:** คนต้องไล่ตรวจเองว่ารายการไหนกระทบระบบจริง ช้าและพลาดง่าย
- **สร้างอะไร:** agent ดึงข้อมูล CISA/CVE เทียบกับรายการซอฟต์แวร์ของบริษัท จัดลำดับความเสี่ยงเอง เปิด ticket พร้อมวิธีแก้ และถามคนก่อนทำขั้นที่มีผลกระทบสูง
- **จุดขาย:** guardrail ชัด ทดสอบกรณีข้อมูลเสีย/API ล่ม

### ข้อ 2: Shop-in-a-Chat
- **ใคร:** แม่ค้าออนไลน์รายเล็กที่ตอบแชทลูกค้าเองทั้งวัน
- **ปัญหา:** ปิดการขายช้า ต้องเช็กสต็อก ราคา สลิป และจัดส่งด้วยมือ
- **สร้างอะไร:** ร้านที่ทั้งกระบวนการเกิดจากแชท ลูกค้าคุยกับ AI รับออเดอร์ เช็กสต็อก ออกใบเสนอราคา ตรวจสลิป และสร้างใบจัดส่ง
- **จุดขาย:** ถ้าเอา AI ออกก็ใช้ไม่ได้

### ข้อ 3: Agri-Credit Assessor (ต่อยอด AOIplanner, NTT AgriBank AI)
- **ใคร:** เกษตรกรไม่มีสลิปเงินเดือน และเจ้าหน้าที่สินเชื่อเกษตร
- **ปัญหา:** ถูกปฏิเสธสินเชื่อเพราะไม่มีเอกสารรายได้ ธนาคารมีต้นทุนตรวจแปลงสูง
- **สร้างอะไร:** รับข้อมูลแปลงและพืช ใช้กฎเกษตร + สภาพอากาศประเมินความเสี่ยงและรายได้คาดการณ์ ออกผลประเมินสินเชื่อพร้อมเหตุผล
- **จุดขาย:** ความรู้โดเมนลึกที่คู่แข่งทำตามยาก

## 3. ไอเดียแนวทางผสม

### 1 + 2: AI Back-Office for SME
- **สร้างอะไร:** ผลิตภัณฑ์ที่ agent ทำงานหลังบ้านครบวงจร (รับใบสั่งซื้อ → ออกใบแจ้งหนี้ → ตามเก็บเงิน → กระทบยอด) ออกแบบรอบ AI ตั้งแต่ต้น ส่งต่อเจ้าของเฉพาะรายการผิดปกติ
- **ระวัง:** กว้าง ต้องตัดให้เหลือ 1 ลูปงาน (เช่น ใบแจ้งหนี้ → ตามเก็บ)

### 2 + 3: ผู้ช่วยวางแผนการเกษตรแบบสนทนา
- **สร้างอะไร:** เกษตรกรพิมพ์/พูดภาษาไทย ("แปลงข้าว 5 ไร่ ฝนแล้ง ควรทำยังไง") AI สร้างแผนให้น้ำ/ปุ๋ย/ตรวจแปลงด้วย rules engine เกษตรจริง ไม่ใช่แชตบอตทั่วไป
- **จุดขาย:** ผลิตภัณฑ์ใหม่ที่ AI เป็นหัวใจ และฉลาดเพราะมีความรู้โดเมน
- **ระวัง:** อย่าให้เป็นแค่แชตบอต

### 3 + 1: Parametric Crop-Insurance Agent
- **สร้างอะไร:** agent เฝ้าข้อมูลฝน/น้ำแบบ real-time ตรวจเงื่อนไขกรมธรรม์ประกันพืชผล เมื่อเข้าเกณฑ์ภัยแล้ง/น้ำท่วมก็เสนอจ่ายเคลมอัตโนมัติ เคสกำกวมส่งให้เจ้าหน้าที่พร้อมเหตุผล และทดสอบย้อนหลังแบบ walk-forward (จาก CN340)
- **จุดขาย:** ลดเวลาเคลมจาก 90–180 วัน ตอบโจทย์ "ไว้ใจได้" ชัดที่สุด

| อันดับ | ไอเดีย | เหตุผล |
